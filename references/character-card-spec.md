# Xchat Hub 角色卡书写规范（Agent 可读版）

> 来源：Xchat Hub 实例（SillyTavern 云化魔改版，2026-08-16 授权抓取）——角色卡字段结构、站内系统预设要求、广场 131 张角色卡实践。
> 目标读者：LLM Agent。本规范让 Agent 能**理解、生成、优化**符合该平台要求的角色卡（JSON 格式，可导入站内/广场）。

---

## 0. 平台背景（先读）

- Xchat Hub 是 **SillyTavern 的云化部署**，角色卡数据结构与 SillyTavern 标准完全一致（v2 格式）。
- 一张角色卡 = 一个 JSON 对象，核心字段见 §1；可附带**世界书**（World Info，§2）与**正则脚本**（Regex，§3）。
- 站内系统预设（「破限」「防神化」「防抢话」「人格内核」「文风（抗八股）」「禁止规则」等）会**叠加在角色卡之上**生效——角色卡写得好不好，直接决定这些预设能不能发挥。
- 站内角色卡广场有评级体系（rank：凡品 / 良品 / 精品等），高评级卡的共同点见 §5。

---

## 1. 角色卡核心字段（SillyTavern v2 标准）

| 字段 | 必填 | 用途 | 书写要点 |
|---|---|---|---|
| `name` | ✅ | 角色名 | 简短、有辨识度；对话中模型会用它自称 |
| `description` | ✅ | **角色描述（最重要字段）** | 一次写清：外貌、年龄、性格、背景经历、说话方式、当前状态。**具体胜于抽象**：写"她总是记得邻居孩子的名字"优于"她很友好"。别用模糊形容词堆砌 |
| `personality` | 建议 | 性格总结 | 短语清单式（如"冷静/毒舌/护短"），供模型快速抓取；与 description 不矛盾 |
| `scenario` | 建议 | 场景设定 | 当前场景、与 {{user}} 的关系、开场情境。**不要预设 {{user}} 的行为**（配合「防抢话」预设） |
| `first_mes` | ✅ | 开场白 | 第一条消息定基调：环境+角色状态+一个钩子（邀请 {{user}} 回应）。建议 100-300 字，别写太长 |
| `mes_example` | 建议 | 示例对话 | 2-5 条示范，**决定模型文风上限**。用站内「文风（抗八股）」标准写：白描、对白推动、无套话。示例里 {{user}} 的言行是"如何被回应"的示范，不是 user 该说什么 |
| `system_prompt` | 可选 | 系统提示词覆盖 | 角色级特殊规则（如角色专属破限）放这里；会替换全局主提示词（注意「优先使用角色提示词」开关） |
| `post_history_instructions` | 可选 | 历史后指令（PHI） | 每次生成前最后注入，优先级最高。写短指令：长度、节奏、不替 user 行动 |
| `creator_notes` | 可选 | 创作者笔记 | 给模型看的作者提示，可放世界观补充或隐藏设定 |
| `tags` | 建议 | 标签 | 用于广场检索与内容分类。风格/题材/关系都要有（如 R18、师生、傲娇、黑暗） |
| `avatar` | 建议 | 头像 | base64 图片 |
| `avatar_prompt` | 可选 | 头像生成提示词 | 站内画图时用 |
| `talkativeness` | 可选 | 话痨度 | 0-1，控制回复篇幅倾向 |
| `extensions` | 可选 | 站内扩展 | 站内用 `rp_hub_temporary_instruction`（临时指令）、`rp_hub_ui_templates`（UI模板）等 |

### 1.1 Agent 书写优先级

```
description > mes_example > first_mes > scenario > personality > PHI > tags
```

前三个字段决定 80% 的角色表现，优先写好。

## 2. 世界书（World Info）规范

站内世界书条目字段（从实例抓取，与 SillyTavern 一致）：

| 字段 | 说明 | 书写要点 |
|---|---|---|
| `comment` | 条目注释 | 只给自己/作者看，不进提示词 |
| `content` | **条目内容** | 触发后注入上下文的信息。写事实、设定、规则，**不要写指令性废话** |
| `keys` | 触发关键词 | 用对话中**可能出现**的具体名词（角色名、地点、物品）。站内示例：文言文卡的 keys=["文言文","翻译","阅读理解"] |
| `secondary_keys` | 次要关键词 | 配合主关键词做 AND/OR 逻辑 |
| `selectiveLogic` | 触发逻辑 | 0=AND、1=OR（站内默认 0） |
| `position` | 注入位置 | `before_char` / `after_char` / `at_depth`（@深度）等；长期设定放前，临时提醒用 at_depth 小深度 |
| `depth` | 深度 | 数字越大注入越靠历史深处 |
| `order` | 排序 | 同位置条目按 order 排序 |
| `constant` | 常驻 | true=永远注入（适合世界观核心） |
| `probability` | 概率 | <100 时按概率触发 |
| `sticky` / `cooldown` | 粘性/冷却 | 跨轮状态控制 |

### 2.1 世界书书写原则

1. **一条一个主题**：拆小拆细，别把整个世界观塞进一条。
2. **关键词要"口语化可达"**：用角色/用户真正会说的词，别用书面语。
3. **内容重事实轻指令**：写"王城禁止魔法，违者处决"而不是"记住魔法是被禁止的"。
4. **优先级分层**：核心世界观 constant=true 或大 depth；场景细节用小 depth 按需触发。

## 3. 正则脚本（Regex）规范

站内正则脚本字段：`scriptName`、`findRegex`、`replaceString`、`placement`（注入位置）、`markdownOnly`（仅显示层）、`promptOnly`（仅提示词层）、`runOnEdit`、`minDepth`/`maxDepth`、`flags`。

用途（站内实践）：
- **输出格式化**：把正文包进 HTML 样式（站内"正文容器""对话高亮""心理活动高亮"等脚本就是干这个的）
- **替换宏**：如 `Auto Replace {{user}}` 把 {{user}} 换成用户昵称
- **隐藏状态栏**：模型输出 `[学习进度: X] [错误数: Y]` 后，用正则在显示层隐藏、在提示词层保留

书写要点：
- 站内脚本大多 `markdownOnly: true`（只影响显示、不进提示词）——需要进提示词的把 `promptOnly` 打开
- 正则要**可回退**：写复杂替换前先想好 match 不到时的行为
- 别把正则写成剧情内容——它是"渲染层"，不是"设定层"

## 4. 站内预设对角色卡的隐含要求（重要）

站内系统预设会叠加在角色卡上，角色卡必须**配合**它们才能发挥，否则会互相打架：

| 预设 | 它要求什么 | 角色卡要避免 |
|---|---|---|
| 「破限」（RP 框架） | 模型严格按角色卡扮演 | 角色卡信息不足、语义模糊 |
| 「防神化」（R-LOGIC） | 角色受限于身体/环境/认知/关系 | ✗ 把角色写成"全知全能、天然正确、无代价" |
| 「防抢话」 | 不替 {{user}} 行动/发言 | ✗ 在 scenario/first_mes 里预设 {{user}} 的行为 |
| 「人格内核」 | 角色有动机、矛盾、边界 | ✗ 无条件顺从、无底线迎合、突然崩坏 |
| 「文风（抗八股）」 | 白描、对白推动、无套话 | ✗ 示例对话写成轻小说口癖/镜头流水账 |
| 「禁止规则」 | 禁"一抹""弧度"等套话 | ✗ 描述里堆砌这些禁词 |
| 「NSFW增强」 | NSFW 场景放开尺度 | 面向成年角色；站内原预设含违规年龄条款（已剔除，勿用） |

**结论：角色卡要写"有血有肉的受限角色"**——有经历、有弱点、有动机、有边界、关系需要积累。这正是高评级卡和低评级卡的分水岭。

---

## 5. 高质量角色卡特征（广场实践总结）

从广场高评级卡归纳：

1. **description 具体可演**：外貌+性格+背景+说话方式一次写清，有冲突点（如"表面温柔的老师，私下是极端惩罚者"）
2. **有戏剧张力设定**：角色有隐藏面、矛盾、执念，给剧情留足空间
3. **tags 完整**：题材/风格/关系/尺度全打上，方便检索
4. **示例对话示范文风**：直接示范"白描+对白推动+心理描写"的写法
5. **世界书支撑设定**：复杂世界观用世界书拆条，不塞进 description
6. **正则做渲染**：输出格式用正则美化，不进设定

## 6. Agent 生成角色卡 Checklist

生成/优化角色卡前逐项自检：

- [ ] `name` 简短有辨识度
- [ ] `description` 覆盖：外貌/年龄/性格/背景/说话方式/当前状态，且**具体不抽象**
- [ ] `description` 含冲突点或隐藏面（不是完美工具人）
- [ ] `scenario` 不预设 {{user}} 的行为
- [ ] `first_mes` 有环境+状态+钩子，100-300 字
- [ ] `mes_example` 2-5 条，示范目标文风（白描、无套话、不替 user 行动）
- [ ] 角色有弱点/边界/动机（配合防神化、人格内核）
- [ ] 无站内禁词（一抹/弧度/不容置疑…）
- [ ] `tags` 完整（题材/风格/关系）
- [ ] 复杂设定已拆进世界书（keys 口语化、一条一主题）
- [ ] 需要时配 PHI（长度/节奏/不替 user 行动）

## 7. 输出格式（JSON 模板）

```json
{
  "name": "角色名",
  "description": "外貌、年龄、性格、背景、说话方式、当前状态（具体、有冲突点）",
  "personality": "短语清单",
  "scenario": "场景与关系，不预设 user 行为",
  "first_mes": "开场白（环境+状态+钩子）",
  "mes_example": "2-5 条示例对话",
  "system_prompt": "",
  "post_history_instructions": "短指令",
  "creator_notes": "",
  "tags": ["题材", "风格", "关系"],
  "avatar_prompt": "",
  "talkativeness": 0.5,
  "extensions": {
    "rp_hub_temporary_instruction": "",
    "world": { "entries": [] }
  }
}
```
